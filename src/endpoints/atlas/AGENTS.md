# Atlas endpoints

What the `/api/atlas/*` reads promise the hosts that render them. The event feed and the registration gate behind the widget are in `src/collections/Events/AGENTS.md`.

## Atlas SEO contract (`GET /api/atlas/seo`)

Serves one atlas route's metadata and body content as data (#645), so a host page can render its own `<head>` server-side. Consumers: WeMeditateWeb's `/map` routes, and the WordPress plugin (13 of 29 known domains).

- **Keyed by the route's terminal segment, not the whole path.** A region slug is unique, and an event id needs no ancestry. Both match the widget's own `resolvePath` rule — a restructured subtree does not 404 every inbound link.
- **The atlas root is a route like any other (#739).** The rule is that **a route made only of reserved segments is the root**, so `/` and anything left empty once `RESERVED_SEGMENTS` is dropped — a bare view route (`/search`, `/register`), a bare legacy prefix (`/events`), or any combination (`/events/areas`) — answer with `type: 'root'`, `id: null`, `route: '/'` and empty `breadcrumbs`. A view of the root is still the root, and so is a prefix that never named a document. Those are the routes most hosts mount, so refusing them left the one page a host links from its own nav inheriting the site's global title and emitting no canonical. **"Names nothing" and "is not a route" are different answers**: a string past the segment cap, or carrying a query or fragment, is still a 404, and the segment cap is measured before view segments are dropped so twenty `/search` rungs cannot reduce to a landing page.
- **The root's copy is seeded, on `sy-atlas-translations`** (`seo.root_title`, `seo.root_description`) — the global that is already localized and already seeded in ten locales. The `seo` group is seed-owned: a seed run replaces the whole column, so new wording goes in `seeds/sy-atlas-translations/data.<locale>.json` and an admin edit lasts only until the next run (#778). Its `description` is `null` in any locale carrying none, exactly as a region's is; only its `title` falls back, because `<title>` is mandatory markup and a blank one is worse than a generic one. **That fallback stays inside the locale first**: a locale with no `seo.root_title` is named by its own `common.chrome.widget_label` — the widget's name for itself — and only a locale carrying neither string reaches English, and then a constant. All ten seeded locales carry both a `root_title` and a `root_description` since #778, so that hop now answers for a locale outside the seed, or one an operator has blanked, and `null` is what an eleventh locale gets rather than the ten. An English title must not displace a host's own localized one. That read opts out of the `clientEnglishFallback` merge with `withoutEnglishFallback(req)`, which would otherwise defeat the `description` rule (`src/endpoints/atlas/seo/rootStrings.ts`).
- **The root's canonical is the caller's own verified embed page** — the mount URL with no route appended, identical in both routing modes, resolved through `canonicalOwnerForClient` so "eligible to publish a canonical" means one thing for the root, the #652 fallback client and every region. A caller that owns no canonical falls through to the **We Meditate surface**, never to the fallback client: that client speaks for regions nobody claims, and somebody else's landing page is not one of those.
- **`where['breadcrumbs.url'][equals]` is not a unique key.** `breadcrumbs` is an array, so `equals` also matches every descendant (`/gb/london` matches London's whole subtree). Use `slug` instead for exactly one region.
- **Nothing in the atlas is localized.** Titles and descriptions are single values the widget translates client-side. The canonical is locale-free, and `alternates` differ only by the widget's `?locale=`.
- **The `alternates` language set is operator-owned**, on `sy-atlas-config.availableLocales` — not the CMS's full locale list, and gated: a language can only be offered once the Sahaj Atlas translations are published in it (#705). An unconfigured row answers `['en']`. See `src/globals/AGENTS.md`.

`GET /api/atlas/sitemap` is the enumeration half (#650). `/sitemap` answers every route this client owns, as the same `webUrl` `/seo` returns as `canonical`. The two can't drift and 404 a crawler (`tests/int/atlas-sitemap.int.spec.ts`).

⚠ **`/api/atlas/wix/*` is a second _shape_ of those two answers, never a second resolver** (#1055). `resolveAtlasSeo` and `resolveAtlasSitemap` are the shared resolutions both pairs read, so a Wix page's `<title>`, canonical and body are the same document WordPress and WeMeditateWeb get — a host that resolved routes itself is how a page's `<head>` comes to describe something its body does not. Wix needs its own shape because its renderer reads no top-level `description` or `noIndex`, it serializes `structuredData` itself, and `$w(…).html` is its only body sink; each of those would break a current reader of the published shapes, and the plugin versions on 13 sites cannot be changed. The generated `backend/routers.js` that calls it is rendered by the Clients Install tab and must agree with it (`docs/rules/clients.md`).

**Unowned regions (#652).** We Meditate is not a client, just two env vars, so unclaimed regions had no sitemap at all. `sy-atlas-config.canonicalFallbackClient` names the client that owns the remainder, and that client's own sitemap then covers it. It is an override: an unset, unpublished, or unverified fallback client leaves the env-var fallback in place. The owners map stays sparse on purpose, so a nearer client's subtree still drops out of an ancestor's sitemap.
